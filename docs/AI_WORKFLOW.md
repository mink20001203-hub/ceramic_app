# AI Workflow

## 목적

이 프로젝트에서 AI는 코드를 대신 완성하는 도구가 아니라, 요구사항을 분해하고 구현 방향을 검토하며 오류 해결 과정을 정리하는 보조 도구로 사용했습니다.

## 사용 도구

| 도구 | 활용 방식 | 근거/상태 |
| --- | --- | --- |
| Codex | 레포 분석, 코드 수정 보조, README/문서 정리, 오류 원인 추적 | 현재 작업 로그 기준 확인 |
| Gemini | 요구사항 정리, 아이디어 비교, 설명 초안 검토 | 확인 필요: 프롬프트/응답 기록은 레포에 없음 |

## 활용 단계

### 1. 요구사항 분해

역할 기반 커머스 앱을 구매자, 판매자, 관리자로 나누고 각 역할의 핵심 흐름을 정리했습니다.

예시:

- 구매자: 상품 탐색 -> 장바구니 -> 주문 -> 주문 상세
- 판매자: 판매 주문 조회 -> 배송 상태 변경 -> 취소 요청 처리
- 관리자: 사용자 역할 관리 -> 운영 콘텐츠 관리

### 2. 구현 보조

AI를 통해 구현 방향을 검토하되, 실제 코드는 프로젝트 구조에 맞게 수정했습니다.

활용 예시:

- Flutter 화면 구성 방식 검토
- Provider 기반 상태 관리 흐름 정리
- Firestore 컬렉션 분리 방향 검토
- 주문 상태값과 상태 로그 설계 보조
- 판매자 sellerId 필터링 방식 검토

### 3. 오류 해결

오류 메시지나 비정상 동작을 바탕으로 원인을 좁히는 데 사용했습니다.

활용 예시:

- `flutter analyze` 실행 환경 문제 정리
- Firestore permission-denied 원인 추적
- sellerId 누락 또는 alias 데이터 문제 점검
- Flutter UI overflow, 텍스트 잘림, 한글 깨짐 문제 정리

### 4. 검토와 문서화

AI로 초안을 만든 뒤, 실제 파일과 실행 결과 기준으로 문서를 수정했습니다.

작성/정리한 문서:

- `README.md`
- `docs/firestore_roles_and_schema.md`
- `docs/final_ui_qa_checklist.md`
- `docs/e2e_execution_log_20260408.md`
- `docs/analyze_environment_troubleshooting.md`

## 검증 원칙

AI 제안은 그대로 신뢰하지 않고 아래 기준으로 확인했습니다.

| 검증 방식 | 목적 |
| --- | --- |
| 코드 직접 확인 | 실제 구현 여부 확인 |
| `flutter analyze` | Dart/Flutter 정적 분석 |
| Firestore rules test | 권한 정책 검증 |
| audit scripts | 주문/판매자 데이터 무결성 확인 |
| manual QA checklist | 실제 사용자 흐름 확인 |

## 면접에서 설명할 포인트

- AI를 사용했지만, 최종 판단은 코드와 테스트 결과 기준으로 했습니다.
- AI는 요구사항을 구조화하고 문제 해결 후보를 찾는 데 유용했습니다.
- 보안 규칙, sellerId 필터링, 주문 상태 흐름은 직접 검증해야 하는 영역으로 보고 테스트 스크립트를 추가했습니다.
- AI 활용 사실을 숨기기보다, 검증과 책임 범위를 명확히 하는 방식으로 사용했습니다.
